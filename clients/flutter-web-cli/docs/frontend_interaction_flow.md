# 前端交互流程文档

## 概述

本文档描述了FileManager Plus项目前端与后端的交互流程，包括用户操作流程、数据流转过程、状态管理等。

## 核心页面结构

### 1. 主页面（HomePage）

**页面路径**: `/home`

**功能描述**: 应用的主入口，提供导航到各个功能模块的入口。

**主要组件**:
- 导航菜单
- 快速操作按钮
- 最近任务列表
- 系统状态概览

**交互流程**:
```
用户打开应用
  -> 显示HomePage
  -> 用户点击导航菜单
  -> 跳转到对应页面
```

### 2. 组合配置页面（ComposePage）

**页面路径**: `/compose`

**功能描述**: 配置流水线和策略，管理源目录。

**主要组件**:
- 源目录配置面板
- 流水线配置面板
- 策略配置面板
- 预览/执行按钮（全局）

**交互流程**:
```
用户打开ComposePage
  -> 显示当前配置
  -> 用户添加/删除源目录
  -> 用户添加/删除流水线节点
  -> 用户配置策略参数
  -> 用户点击"预览"按钮
  -> 发送预览请求到后端
  -> 跳转到PreviewPage显示结果
  -> 用户点击"执行"按钮
  -> 发送执行请求到后端
  -> 跳转到PreviewPage显示执行结果
```

**全局操作按钮**:
- **预览按钮**: 触发预览分析，跳转到预览页面
- **执行按钮**: 触发执行任务，跳转到预览页面
- **停止按钮**: 中止当前运行的任务

### 3. 预览页面（PreviewPage）

**页面路径**: `/preview`

**功能描述**: 显示预览或执行结果，支持查看详细信息和执行操作。

**主要组件**:
- 预览/执行按钮（全局）
- 变更记录表格
- 状态过滤器
- 搜索框
- 进度条
- 操作按钮（删除原始文件、删除目标文件、执行选中）

**交互流程**:
```
用户打开PreviewPage
  -> 显示当前任务状态
  -> 如果任务运行中，显示进度条
  -> 用户可以点击"停止"按钮中止任务
  -> 任务完成后，显示变更记录列表
  -> 用户可以使用过滤器筛选记录
  -> 用户可以搜索特定文件
  -> 用户可以选中记录并执行操作
  -> 用户可以点击"预览"按钮重新预览
  -> 用户可以点击"执行"按钮执行变更
```

**全局操作按钮**:
- **预览按钮**: 重新触发预览分析
- **执行按钮**: 执行预览结果（仅在预览完成后可用）
- **停止按钮**: 中止当前运行的任务

## 用户操作流程

### 流程1: 配置并预览

```
1. 用户打开ComposePage
2. 用户添加源目录
3. 用户添加流水线节点
4. 用户配置策略参数
5. 用户点击"预览"按钮
6. 系统发送预览请求到后端
7. 后端开始扫描文件并应用策略
8. 系统跳转到PreviewPage
9. PreviewPage显示任务进度
10. 任务完成后显示变更记录列表
11. 用户可以查看和筛选变更记录
```

### 流程2: 配置并执行

```
1. 用户打开ComposePage
2. 用户添加源目录
3. 用户添加流水线节点
4. 用户配置策略参数
5. 用户点击"执行"按钮
6. 系统发送执行请求到后端
7. 后端开始扫描文件并应用策略
8. 系统跳转到PreviewPage
9. PreviewPage显示任务进度
10. 任务完成后显示执行结果
11. 用户可以查看执行结果
```

### 流程3: 预览后执行

```
1. 用户完成预览流程
2. 用户在PreviewPage查看变更记录
3. 用户确认变更无误
4. 用户点击"执行"按钮
5. 系统发送执行请求到后端
6. 后端执行预览结果
7. PreviewPage显示执行进度
8. 执行完成后显示最终结果
```

### 流程4: 中止任务

```
1. 用户在ComposePage或PreviewPage
2. 用户发现任务执行有问题
3. 用户点击"停止"按钮
4. 系统发送停止请求到后端
5. 后端中止当前任务
6. PreviewPage显示任务已中止
7. 用户可以查看已处理的部分结果
```

## 数据流转过程

### 预览流程数据流转

```
前端（ComposePage）
  -> POST /api/pipeline/analyze
  -> 请求体: {sourceDirectories, pipeline}
  
后端（PipelineController）
  -> 接收请求
  -> 创建预览任务
  -> 扫描源目录文件
  -> 逐个文件通过所有策略处理
  -> 生成变更记录
  -> 更新任务状态和进度
  -> 通过WebSocket推送进度
  
前端（PreviewPage）
  -> 接收WebSocket进度更新
  -> 更新进度条和状态
  -> 任务完成后获取变更记录
  -> GET /api/pipeline/changes
  -> 显示变更记录列表
```

### 执行流程数据流转

```
前端（ComposePage或PreviewPage）
  -> POST /api/pipeline/execute
  -> 请求体: {sourceDirectories, pipeline}
  
后端（PipelineController）
  -> 接收请求
  -> 创建执行任务
  -> 扫描源目录文件
  -> 逐个文件通过所有策略执行
  -> 实际修改文件
  -> 更新任务状态和进度
  -> 通过WebSocket推送进度
  
前端（PreviewPage）
  -> 接收WebSocket进度更新
  -> 更新进度条和状态
  -> 任务完成后获取执行结果
  -> GET /api/pipeline/changes
  -> 显示执行结果
```

## 状态管理

### 任务状态

| 状态 | 说明 | 显示 |
|------|------|------|
| READY | 准备就绪 | 显示"准备就绪" |
| PREVIEWING | 预览中 | 显示进度条和"预览中" |
| PREVIEW_COMPLETED | 预览完成 | 显示"预览完成"和变更记录 |
| PREVIEW_FAILED | 预览失败 | 显示"预览失败"和错误信息 |
| EXECUTING | 执行中 | 显示进度条和"执行中" |
| EXECUTION_COMPLETED | 执行完成 | 显示"执行完成"和执行结果 |
| EXECUTION_FAILED | 执行失败 | 显示"执行失败"和错误信息 |
| CANCELLED | 已中止 | 显示"已中止" |

### 按钮状态

| 按钮 | 可用条件 | 不可用条件 |
|------|----------|------------|
| 预览 | 任务未运行 | 任务运行中 |
| 执行 | 任务未运行且预览已完成 | 任务运行中或预览未完成 |
| 停止 | 任务运行中 | 任务未运行 |

## WebSocket通信

### 任务进度推送

**主题**: `/topic/task/progress`

**消息格式**:
```json
{
  "taskId": "task-123456",
  "taskName": "preview",
  "status": "PREVIEWING",
  "step": "扫描文件",
  "message": "正在扫描文件...",
  "progress": 50,
  "total": 1000,
  "processed": 500,
  "hasChanges": true,
  "changesCount": 50
}
```

### 任务状态更新

**主题**: `/topic/task/status`

**消息格式**:
```json
{
  "taskId": "task-123456",
  "status": "PREVIEW_COMPLETED",
  "message": "预览完成，共发现 50 个变更"
}
```

## 错误处理

### 网络错误

```
用户操作
  -> 网络请求失败
  -> 显示错误提示
  -> 提供重试按钮
  -> 用户点击重试
  -> 重新发送请求
```

### 任务失败

```
用户操作
  -> 任务执行失败
  -> 后端返回错误信息
  -> 前端显示错误详情
  -> 用户查看失败原因
  -> 用户修正配置后重试
```

### 文件操作错误

```
任务执行中
  -> 文件操作失败
  -> 记录失败原因到ChangeRecord
  -> 继续处理其他文件
  -> 任务完成后显示失败记录
  -> 用户可以查看失败原因
```
