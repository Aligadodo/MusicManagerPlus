# 迭代流程规范

## 概述

本文档定义了FileManager Plus项目的迭代开发流程，确保开发过程规范、高效、可追溯。

## 迭代流程

### 1. 需求分析

**目标**: 明确功能需求和技术方案

**步骤**:
1. 分析用户需求
2. 确定功能范围
3. 评估技术可行性
4. 制定实现方案

**输出**:
- 需求文档
- 技术方案文档

### 2. 设计阶段

**目标**: 完成系统设计和接口定义

**步骤**:
1. 系统架构设计
2. 数据库设计（如需要）
3. API接口设计
4. UI/UX设计

**输出**:
- 架构设计文档
- API文档
- UI设计稿

### 3. 开发阶段

**目标**: 完成功能开发

**步骤**:
1. 创建开发分支
2. 编写代码
3. 单元测试
4. 代码审查
5. 编译部署

**输出**:
- 功能代码
- 单元测试代码

**操作规范**:
- 使用 `./bin/macos/deploy-all.sh` 进行快速部署
- 使用 `./bin/macos/check-services.sh` 检查服务状态
- 禁止手动 kill 进程，必须使用项目脚本

### 4. 测试阶段

**目标**: 验证功能正确性

**步骤**:
1. 集成测试
2. 系统测试
3. 回归测试
4. 修复Bug

**输出**:
- 测试报告
- Bug修复记录

### 5. 文档更新

**目标**: 更新相关文档

**步骤**:
1. 更新设计文档
2. 更新API文档
3. 更新用户文档
4. 更新开发文档
5. 更新迭代文档

**输出**:
- 更新后的文档

**文档更新要求**:
- **架构设计文档更新**: 当架构发生变化时，必须更新`design/current-architecture.md`
  - 更新插件接口定义
  - 更新ChangeRecord模型说明
  - 更新ExecutionContext说明
  - 更新流水线执行流程
  - 更新数据流设计

- **模块设计文档更新**: 当新增或修改模块时，必须更新`design/module-design.md`
  - 更新模块架构图
  - 更新模块职责说明
  - 更新接口定义
  - 更新实现方式

- **功能设计文档更新**: 当新增或修改功能时，必须更新`design/current-features.md`
  - 更新功能描述
  - 更新主要参数
  - 更新核心特性
  - 更新使用场景

- **迭代文档创建**: 每次迭代必须在`design/iteration/{YYYY-MM}/`目录下创建迭代文档
  - 使用模板`design/iteration/template.md`
  - 记录需求分析
  - 记录设计方案
  - 记录实现过程
  - 记录测试结果
  - 记录遇到的问题和解决方案

- **协议接口文档更新**: 当接口发生变化时，必须更新`backend/docs/protocol_interface.md`
  - 更新API端点
  - 更新请求/响应格式
  - 更新枚举类型
  - 更新错误码

- **前端交互流程文档更新**: 当前端交互发生变化时，必须更新`backend/docs/frontend_interaction_flow.md`
  - 更新页面流程
  - 更新交互逻辑
  - 更新数据流

### 6. 发布阶段

**目标**: 发布新版本

**步骤**:
1. 代码合并
2. 版本打标
3. 构建发布包
4. 发布通知

**输出**:
- 发布版本
- 发布说明

## 注意事项

### 分支管理

- 从主分支创建功能分支
- 功能分支命名: `feature/{功能名称}`
- 完成后合并到主分支
- 及时删除已合并的分支

### 代码审查

- 所有代码必须经过审查
- 审查关注点: 代码质量、安全性、性能
- 审查通过后方可合并

### 测试要求

- 单元测试覆盖率 >= 70%
- 集成测试覆盖核心流程
- 回归测试确保不引入新问题
- 测试用例必须覆盖所有新增和修改的功能
- 测试用例必须覆盖所有边界情况和异常情况
- 测试用例必须包含正常流程和异常流程

**测试用例要求**:
- **单元测试**: 为每个新增或修改的类编写单元测试
  - 测试所有公共方法
  - 测试边界情况
  - 测试异常情况
  - 使用Mock对象隔离依赖

- **集成测试**: 为核心流程编写集成测试
  - 测试流水线执行流程
  - 测试插件执行流程
  - 测试前后端交互流程
  - 测试文件扫描、过滤、处理流程

- **回归测试**: 确保不引入新问题
  - 运行所有现有测试用例
  - 确保所有测试通过
  - 对比新老架构功能迁移完整性

**测试用例补充**:
- 当迁移老架构功能时，必须补充对应的测试用例
- 当修复Bug时，必须添加回归测试用例
- 当优化性能时，必须添加性能测试用例
- 当添加新功能时，必须添加功能测试用例

### 文档要求

- 代码变更必须同步更新文档
- API变更必须更新API文档
- 新功能必须更新用户文档
