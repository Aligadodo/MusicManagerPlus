# 文档标准

## 概述

本文档定义了FileManager Plus项目的文档编写标准，确保文档质量、一致性和可维护性。

## 文档分类

### 1. 设计文档

**用途**: 记录系统设计和架构决策

**包含内容**:
- 系统架构
- 模块设计
- 接口定义
- 数据模型

**存放位置**: `design/{framework}/system-overview/`

### 2. 业务流程文档

**用途**: 描述业务逻辑和流程

**包含内容**:
- 业务流程图
- 状态转换图
- 业务规则
- 异常处理

**存放位置**: `design/{framework}/business-flow/`

### 3. 界面交互文档

**用途**: 描述UI设计和交互逻辑

**包含内容**:
- 界面设计稿
- 交互流程
- 组件规范
- 样式规范

**存放位置**: `design/{framework}/ui-interaction/`

### 4. 模块详细设计文档

**用途**: 描述具体模块的实现细节

**包含内容**:
- 模块职责
- 类设计
- 方法说明
- 关键算法

**存放位置**: `design/{framework}/module-detail/`

## 文档格式规范

### Markdown格式

#### 标题层级

**规则**: 最多使用6级标题

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

#### 列表

**规则**: 使用有序列表和无序列表

```markdown
无序列表:
- 项目1
- 项目2
  - 子项目1
  - 子项目2

有序列表:
1. 第一步
2. 第二步
3. 第三步
```

#### 代码块

**规则**: 指定语言类型

```markdown
\`\`\`java
public class Example {
}
\`\`\`

\`\`\`dart
class Example {
}
\`\`\`
```

#### 表格

**规则**: 使用Markdown表格格式

```markdown
| 列1 | 列2 | 列3 |
|------|------|------|
| 数据1 | 数据2 | 数据3 |
| 数据4 | 数据5 | 数据6 |
```

### 文档结构

#### 标准结构

```markdown
# 文档标题

## 概述
简要说明文档的目的和内容

## 背景说明
说明文档的背景和上下文

## 详细内容
文档的主要内容

## 示例
提供实际示例

## 注意事项
列出需要注意的点

## 相关文档
列出相关文档的链接

---
**文档版本**: 1.0
**最后更新**: YYYY-MM-DD
**维护者**: FileManager Plus Team
```

## 文档命名规范

### 文件命名

**规则**: 使用小写字母和连字符

```
正确:
system-overview.md
business-flow.md
ui-interaction.md

错误:
SystemOverview.md
Business_Flow.md
UIInteraction.md
```

### 目录命名

**规则**: 使用小写字母和连字符

```
正确:
system-overview/
business-flow/
ui-interaction/

错误:
SystemOverview/
Business_Flow/
UIInteraction/
```

## 文档内容规范

### 语言要求

**规则**: 使用中文编写文档

```
正确:
本文档定义了FileManager Plus项目的文档编写标准

错误:
This document defines the documentation standards for FileManager Plus project
```

### 简洁性

**规则**: 避免冗余和废话

```
正确:
使用4个空格缩进

错误:
为了保持代码的一致性和可读性，我们应该使用4个空格进行缩进，而不是使用Tab字符，这样可以确保代码在不同编辑器中显示一致
```

### 准确性

**规则**: 确保信息准确无误

```
正确:
API端点: http://localhost:8080/api/files

错误:
API端点: http://localhost:8080/api/file
```

### 完整性

**规则**: 提供完整的信息

```
正确:
创建新策略需要完成以下步骤：
1. 创建策略类
2. 实现必要接口
3. 注册策略

错误:
创建新策略需要完成相关步骤
```

## 文档更新规范

### 更新时机

**规则**: 代码变更时同步更新文档

```
需要更新文档的情况:
- 新增功能
- 修改接口
- 变更配置
- 修复Bug
- 优化性能
```

### 更新内容

**规则**: 更新所有相关文档

```
更新检查清单:
- [ ] 更新设计文档
- [ ] 更新API文档
- [ ] 更新用户文档
- [ ] 更新开发文档
- [ ] 更新示例代码
```

### 版本管理

**规则**: 记录文档版本历史

```markdown
## 版本历史

| 版本 | 日期 | 修改内容 | 作者 |
|------|------|---------|------|
| 1.0 | 2026-02-03 | 初始版本 | FileManager Plus Team |
| 1.1 | 2026-02-04 | 添加新功能说明 | FileManager Plus Team |
```

请确保文档符合上述标准，并保持文档的质量和可维护性。
