# 全流程验证测试方案

## 1. 测试目标

验证前后端插件系统的完整功能，确保：
- 插件的预览功能正确识别待处理的文件
- 插件的执行功能正确处理文件
- 参数联动机制正常工作
- 前后端数据传输正确

## 2. 测试环境

- 后端：Spring Boot 应用（端口8080）
- 前端：Flutter Web 应用（端口8081）
- 测试数据目录：`/tmp/test_data/`

## 3. 测试插件清单

### 3.1 核心插件
- FileCleanupPlugin（文件清理插件）
- FileUnzipPlugin（文件解压插件）

### 3.2 其他插件
- DuplicatePlugin（文件去重插件）
- AdvancedRenamePlugin（高级重命名插件）
- FileRenamePlugin（文件重命名插件）
- FileMigratePlugin（文件迁移插件）
- FileTypeFixPlugin（文件类型修复插件）
- AlbumDirNormalizePlugin（专辑目录规范化插件）
- CollectionNamingPlugin（集合命名插件）
- CueFileRenamePlugin（CUE文件重命名插件）
- CueSplitterPlugin（CUE分割插件）
- NcmIntegratedPlugin（NCM集成插件）
- FileCollectionPlugin（文件集合插件）
- MetadataScraperPlugin（元数据抓取插件）
- AudioConverterPlugin（音频转换插件）

## 4. 测试用例设计

### 4.1 FileCleanupPlugin 测试用例

#### 测试用例 1：文件去重模式
**前置条件**：
- 创建测试目录：`/tmp/test_data/dedup_files/`
- 创建重复文件：
  - `song1.mp3` (100KB)
  - `song1 (1).mp3` (150KB)
  - `song2.mp3` (200KB)
  - `song2 (Copy).mp3` (180KB)

**测试步骤**：
1. 启动后端服务
2. 启动前端服务
3. 在前端选择 FileCleanupPlugin
4. 配置参数：
   - 清理模式：文件去重
   - 保留体积/质量最佳的副本：勾选
   - 保留日期最早/最晚的副本：不勾选
   - 文件名转小写：勾选
5. 选择测试目录
6. 点击"预览"按钮
7. 验证预览结果：
   - 应该识别出2组重复文件
   - 每组应该保留最大的文件
8. 点击"执行"按钮
9. 验证执行结果：
   - `song1 (1).mp3` 应该被保留（150KB）
   - `song2.mp3` 应该被保留（200KB）
   - 其他文件应该被删除或移动到回收站

**预期结果**：
- 预览功能正确识别重复文件
- 执行功能正确删除重复文件
- 保留的文件符合配置规则

#### 测试用例 2：空目录清理模式
**前置条件**：
- 创建测试目录：`/tmp/test_data/empty_dirs/`
- 创建空目录：
  - `empty_dir1/`
  - `empty_dir2/`
  - `non_empty_dir/`（包含一个文件）

**测试步骤**：
1. 配置参数：
   - 清理模式：清理空目录
2. 选择测试目录
3. 点击"预览"按钮
4. 验证预览结果：
   - 应该识别出2个空目录
5. 点击"执行"按钮
6. 验证执行结果：
   - 空目录应该被删除
   - 非空目录应该保留

**预期结果**：
- 预览功能正确识别空目录
- 执行功能正确删除空目录

#### 测试用例 3：参数联动测试
**前置条件**：
- 使用测试用例1的测试数据

**测试步骤**：
1. 选择 FileCleanupPlugin
2. 验证参数联动：
   - 选择"文件去重"模式时，应该显示"保留体积/质量最佳的副本"参数
   - 选择"清理空目录"模式时，应该隐藏"保留体积/质量最佳的副本"参数
   - 勾选"文件名转小写"时，应该自动取消"文件名转大写"
   - 勾选"文件名转大写"时，应该自动取消"文件名转小写"

**预期结果**：
- 参数可见性联动正常工作
- 参数互斥联动正常工作

### 4.2 FileUnzipPlugin 测试用例

#### 测试用例 1：Java引擎解压ZIP文件
**前置条件**：
- 创建测试目录：`/tmp/test_data/unzip/`
- 创建测试ZIP文件：`test.zip`（包含几个文件）

**测试步骤**：
1. 选择 FileUnzipPlugin
2. 配置参数：
   - 解压引擎：Java内置引擎
   - 输出模式：当前目录
   - 智能文件夹：勾选
3. 选择测试ZIP文件
4. 点击"预览"按钮
5. 验证预览结果：
   - 应该显示解压目标路径
6. 点击"执行"按钮
7. 验证执行结果：
   - ZIP文件应该被解压
   - 解压后的文件应该在目标目录

**预期结果**：
- 预览功能正确显示解压路径
- 执行功能正确解压文件

**前置条件**：
- 安装7-Zip或Bandizip

**测试步骤**：
1. 配置参数：
   - 解压引擎：7-Zip引擎
   - 可执行文件路径：应该自动检测到7-Zip路径
2. 验证自动检测功能：
   - 选择外部引擎时，应该自动检测工具路径
3. 执行解压操作

**预期结果**：
- 自动检测功能正常工作
- 外部引擎正常解压文件

#### 测试用例 3：参数联动测试
**测试步骤**：
1. 选择 FileUnzipPlugin
2. 验证参数联动：
   - 选择"Java内置引擎"时，应该隐藏"可执行文件路径"参数
   - 选择"7-Zip引擎"时，应该显示"可执行文件路径"参数
   - 选择"指定目录"输出模式时，应该显示"自定义路径"参数
   - 选择"当前目录"输出模式时，应该隐藏"自定义路径"参数

**预期结果**：
- 参数可见性联动正常工作
- 自动检测联动正常工作

## 7. 回归测试

每次代码变更后，需要执行以下回归测试：
1. 核心插件测试（FileCleanupPlugin、FileUnzipPlugin）
2. 参数联动测试
3. 前后端集成测试

## 8. 测试数据清理

测试完成后，清理测试数据：
```bash
rm -rf /tmp/test_data
```

## 9. 注意事项

1. 测试数据应该与实际使用场景相似
2. 测试应该覆盖正常情况和异常情况
3. 测试结果应该详细记录
4. 发现问题应该及时修复并重新测试
