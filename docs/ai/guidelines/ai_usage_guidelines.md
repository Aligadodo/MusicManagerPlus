# AI 工具使用指导方针

## 1. 概述

本指导方针旨在帮助 AI 工具（如 Trae、Claude 等）更好地理解和使用 MusicManagerPlus 项目的文档和规范，提高开发效率和代码质量。

## 2. 文档结构

AI 工具应首先了解项目的文档结构，以便快速定位和检索相关信息：

- **docs/INDEX.md**：文档总索引，包含所有文档的分类和链接
- **docs/iteration/**：迭代记录，按月份组织
- **docs/standard/**：标准规范，包括代码风格、文档风格等
- **docs/skill/**：技能开发指南
- **docs/migration/**：迁移相关文档
- **docs/design/**：设计文档
- **docs/testing/**：测试相关文档
- **docs/ai/**：AI 工具相关文档

## 3. 文档检索策略

### 3.1 按功能分类检索

- **架构设计**：查看 `backend/docs/architecture/` 目录
- **API 设计**：查看 `backend/docs/api/` 目录
- **前端设计**：查看 `backend/docs/guides/frontend_page_design.md`
- **测试文档**：查看 `docs/testing/` 和 `backend/docs/test/` 目录

### 3.2 按时间检索

- **迭代记录**：查看 `docs/iteration/{年份}-{月份}/` 目录
- **最新迭代**：查看 `docs/iteration/` 目录下的最新月份

### 3.3 按类型检索

- **规范文档**：查看 `docs/standard/` 目录
- **开发指南**：查看 `docs/skill/` 目录
- **迁移文档**：查看 `docs/migration/` 目录

## 4. 代码规范遵循

AI 工具在生成代码时应遵循以下规范：

- **后端 Java 代码**：参考 `docs/standard/code-style/code-standard.md`
- **前端 Dart 代码**：遵循 Flutter 官方规范和项目现有的代码风格
- **命名规范**：使用有意义的变量和方法名，遵循驼峰命名法
- **代码结构**：保持代码结构清晰，合理划分模块
- **注释规范**：添加必要的注释，解释代码的功能和设计意图

## 5. 文档编写规范

AI 工具在编写文档时应遵循以下规范：

- **格式**：使用 Markdown 格式
- **结构**：保持文档结构清晰，层次分明
- **命名**：文件名使用小写字母，单词间用连字符分隔
- **内容**：内容要准确、完整，与代码实现保持一致
- **链接**：添加必要的链接，方便用户导航

## 6. 迭代流程遵循

AI 工具在参与迭代时应遵循以下流程：

1. **需求分析**：理解用户需求，参考相关文档
2. **设计方案**：制定实现方案，考虑架构和性能
3. **代码实现**：编写代码，遵循代码规范
4. **测试验证**：运行测试，确保功能正常
5. **文档更新**：更新相关文档，保持一致性
6. **代码审查**：检查代码质量，确保符合规范

## 7. 常见任务处理指南

### 7.1 代码开发

- **新功能开发**：参考相关设计文档和开发指南
- **bug 修复**：分析问题原因，提出解决方案，验证修复效果
- **代码重构**：保持代码的可维护性，遵循重构原则

### 7.2 文档编写

- **设计文档**：详细描述功能设计、架构和实现方案
- **用户指南**：提供清晰的使用说明和示例
- **测试文档**：编写测试用例和测试计划

### 7.3 问题排查

- **错误分析**：查看日志和错误信息，定位问题原因
- **解决方案**：提出合理的解决方案，考虑兼容性和性能
- **验证测试**：运行测试，确保问题已解决

## 8. 输出质量要求

AI 工具的输出应满足以下要求：

- **准确性**：内容准确，与项目实际情况一致
- **完整性**：提供完整的解决方案，包括代码、文档和测试
- **一致性**：保持代码和文档的一致性
- **可读性**：代码和文档的格式清晰，易于阅读和理解
- **可维护性**：代码结构合理，易于维护和扩展
