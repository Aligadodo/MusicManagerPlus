# 功能回归测试SOP（标准操作流程）

## 1. 目的

确保每次代码变更后，系统的核心功能保持正常，防止引入新的缺陷。

## 2. 适用范围

适用于所有涉及以下内容的代码变更：
- 插件系统的修改
- 前端参数配置页面的修改
- 后端插件接口的修改
- 参数联动机制的修改
- 数据传输协议的修改

## 3. 回归测试级别

### 3.1 快速回归测试（每次提交）
- 执行时间：10-15分钟
- 测试范围：核心插件的基本功能
- 测试用例：
  - FileCleanupPlugin：文件去重模式
  - FileUnzipPlugin：Java引擎解压
  - 参数联动：可见性联动、互斥联动

### 3.2 完整回归测试（每次发布）
- 执行时间：30-45分钟
- 测试范围：所有插件的所有功能
- 测试用例：参考[TEST_PLAN.md](TEST_PLAN.md)

### 3.3 深度回归测试（重大变更）
- 执行时间：1-2小时
- 测试范围：所有功能 + 边界情况 + 性能测试
- 测试用例：完整回归测试 + 额外的边界测试

## 4. 回归测试流程

### 4.1 测试准备

#### 4.1.1 环境检查
- [ ] 后端服务是否正常运行（端口8080）
- [ ] 前端服务是否正常运行（端口8081）
- [ ] 数据库连接是否正常
- [ ] 测试数据是否准备就绪

#### 4.1.2 测试数据准备
```bash
# 创建测试数据目录
mkdir -p /tmp/test_data/dedup_files
mkdir -p /tmp/test_data/empty_dirs
mkdir -p /tmp/test_data/unzip
mkdir -p /tmp/test_data/duplicate

# 创建重复文件测试数据
echo "test content 1" > /tmp/test_data/dedup_files/song1.mp3
echo "test content 2" > /tmp/test_data/dedup_files/song1_copy.mp3
echo "test content 3" > /tmp/test_data/dedup_files/song2.mp3

# 创建空目录测试数据

mkdir -p /tmp/test_data/empty_dirs/empty_dir2

# 创建ZIP测试数据

```

### 4.2 快速回归测试步骤

#### 4.2.1 FileCleanupPlugin测试
1. **文件去重模式测试**
   - [ ] 打开前端应用
   - [ ] 选择FileCleanupPlugin
   - [ ] 配置参数：
     - 清理模式：文件去重
     - 保留体积/质量最佳的副本：勾选
     - 保留日期最早/最晚的副本：不勾选
   - [ ] 选择测试目录：`/tmp/test_data/dedup_files`
   - [ ] 点击"预览"按钮
   - [ ] 验证预览结果：应该识别出2组重复文件
   - [ ] 点击"执行"按钮
   - [ ] 验证执行结果：应该保留最大的文件，删除其他文件

2. **空目录清理模式测试**
   - [ ] 配置参数：
     - 清理模式：清理空目录
   - [ ] 选择测试目录：`/tmp/test_data/empty_dirs`
   - [ ] 点击"预览"按钮
   - [ ] 验证预览结果：应该识别出2个空目录
   - [ ] 点击"执行"按钮
   - [ ] 验证执行结果：空目录应该被删除

#### 4.2.2 FileUnzipPlugin测试
1. **Java引擎解压测试**
   - [ ] 选择FileUnzipPlugin
   - [ ] 配置参数：
     - 解压引擎：Java内置引擎
     - 输出模式：当前目录
     - 智能文件夹：勾选
   - [ ] 选择测试文件：`/tmp/test_data/unzip/test.zip`
   - [ ] 点击"预览"按钮
   - [ ] 验证预览结果：应该显示解压目标路径
   - [ ] 点击"执行"按钮
   - [ ] 验证执行结果：ZIP文件应该被解压

#### 4.2.3 参数联动测试
1. **可见性联动测试**
   - [ ] 选择FileCleanupPlugin
   - [ ] 验证：选择"文件去重"模式时，显示"保留体积/质量最佳的副本"参数
   - [ ] 验证：选择"清理空目录"模式时，隐藏"保留体积/质量最佳的副本"参数
   - [ ] 选择FileUnzipPlugin
   - [ ] 验证：选择"Java内置引擎"时，隐藏"可执行文件路径"参数
   - [ ] 验证：选择"7-Zip引擎"时，显示"可执行文件路径"参数

2. **互斥联动测试**
   - [ ] 选择FileCleanupPlugin
   - [ ] 验证：勾选"文件名转小写"时，自动取消"文件名转大写"
   - [ ] 验证：勾选"文件名转大写"时，自动取消"文件名转小写"

3. **自动检测联动测试**
   - [ ] 选择FileUnzipPlugin
   - [ ] 验证：选择"7-Zip引擎"时，自动检测工具路径（如果已安装）

### 4.5 测试通过标准

#### 4.5.1 快速回归测试通过标准
- 所有核心插件的基本功能正常
- 参数联动机制正常
- 没有严重的错误或异常
- 通过率 ≥ 90%

#### 4.5.2 完整回归测试通过标准
- 所有插件的所有功能正常
- 参数联动机制正常
- 前后端数据传输正确
- 没有严重的错误或异常
- 通过率 ≥ 95%

#### 4.5.3 深度回归测试通过标准
- 满足完整回归测试通过标准
- 边界情况处理正确
- 性能指标符合要求
- 通过率 ≥ 98%

### 4.6 问题处理流程

#### 4.6.1 问题分类
- **严重问题**：系统崩溃、数据丢失、功能完全不可用
- **主要问题**：功能部分不可用、影响用户体验
- **次要问题**：界面显示问题、提示信息不准确
- **建议**：功能优化建议、用户体验改进建议

#### 4.6.2 问题处理
1. 记录问题详情
2. 分析问题原因
3. 制定修复方案
4. 修复问题
5. 重新测试
6. 验证修复效果

#### 4.6.3 问题跟踪
使用问题跟踪系统（如JIRA、GitHub Issues）跟踪问题的处理进度。

### 4.7 测试数据清理

测试完成后，清理测试数据：
```bash
rm -rf /tmp/test_data
```

## 5. 回归测试频率

### 5.1 强制回归测试
- 每次代码合并到主分支
- 每次发布新版本
- 重大功能变更后

### 5.2 建议回归测试
- 每周至少一次
- 修复bug后
- 性能优化后

## 6. 自动化测试

### 6.1 自动化测试目标
- 快速回归测试可以完全自动化
- 完整回归测试可以部分自动化
- 减少人工测试的工作量

### 6.2 自动化测试工具
- 后端单元测试：JUnit
- 前端单元测试：Flutter test
- 集成测试：Postman、Selenium

### 6.3 自动化测试脚本
```bash
# 快速回归测试脚本
#!/bin/bash
# quick_regression_test.sh

echo "开始快速回归测试..."

# 准备测试数据
./prepare_test_data.sh

# 启动服务
./start_services.sh

# 执行测试
./run_quick_tests.sh

# 清理测试数据
./cleanup_test_data.sh

echo "快速回归测试完成！"
```

## 7. 注意事项

1. 测试应该在干净的环境中进行
2. 测试数据应该与实际使用场景相似
3. 测试结果应该详细记录
4. 发现问题应该及时修复并重新测试
5. 回归测试应该定期执行
6. 测试用例应该根据实际情况更新
