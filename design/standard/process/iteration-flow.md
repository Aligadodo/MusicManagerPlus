# 迭代流程规范

## 概述

本文档定义了FileManager Plus项目的迭代开发流程，确保开发过程规范、高效、可追溯。

## 迭代流程

### 1. 需求分析

**目标**: 明确功能需求和技术方案

**步骤**:
1. 分析用户需求
2. 确定功能范围
3. 评估技术可行性
4. 制定实现方案

**输出**:
- 需求文档
- 技术方案文档

### 2. 设计阶段

**目标**: 完成系统设计和接口定义

**步骤**:
1. 系统架构设计
2. 数据库设计（如需要）
3. API接口设计
4. UI/UX设计

**输出**:
- 架构设计文档
- API文档
- UI设计稿

### 3. 开发阶段

**目标**: 完成功能开发

**步骤**:
1. 创建开发分支
2. 编写代码
3. 单元测试
4. 代码审查
5. 编译部署

**输出**:
- 功能代码
- 单元测试代码

**操作规范**:
- 使用 `./bin/macos/deploy-all.sh` 进行快速部署
- 使用 `./bin/macos/check-services.sh` 检查服务状态
- 禁止手动 kill 进程，必须使用项目脚本

### 4. 测试阶段

**目标**: 验证功能正确性

**步骤**:
1. 集成测试
2. 系统测试
3. 回归测试
4. 修复Bug

**输出**:
- 测试报告
- Bug修复记录

### 5. 文档更新

**目标**: 更新相关文档

**步骤**:
1. 更新设计文档
2. 更新API文档
3. 更新用户文档
4. 更新开发文档

**输出**:
- 更新后的文档

### 6. 发布阶段

**目标**: 发布新版本

**步骤**:
1. 代码合并
2. 版本打标
3. 构建发布包
4. 发布通知

**输出**:
- 发布版本
- 发布说明

## 注意事项

### 分支管理

- 从主分支创建功能分支
- 功能分支命名: `feature/{功能名称}`
- 完成后合并到主分支
- 及时删除已合并的分支

### 代码审查

- 所有代码必须经过审查
- 审查关注点: 代码质量、安全性、性能
- 审查通过后方可合并

### 测试要求

- 单元测试覆盖率 >= 70%
- 集成测试覆盖核心流程
- 回归测试确保不引入新问题

### 文档要求

- 代码变更必须同步更新文档
- API变更必须更新API文档
- 新功能必须更新用户文档

```
你正在参与FileManager Plus项目的迭代开发。请按照以下流程进行：

1. 需求分析阶段：
   - 理解用户需求，明确功能范围

   - 进行集成测试和系统测试
   - 执行回归测试，确保不引入新问题
   - 修复发现的Bug

5. 文档更新：
   - 更新设计文档，反映实际实现
   - 更新API文档，包括新增或修改的接口
   - 更新用户文档，说明新功能使用方法

6. 发布阶段：
   - 合并代码到主分支
   - 打版本标签
   - 编写发布说明

注意事项：
- 所有代码必须经过审查
- 单元测试覆盖率不低于70%
- 文档必须与代码同步更新
- 遵循项目的代码规范和设计规范
- **必须遵循开发操作规范**: 参考 design/standard/process/development-operations.md
- **必须使用项目脚本**: 禁止手动 kill 进程
```
