# FileManager Plus 技术迁移完整设计文档与实施计划

## 1. 项目现状分析

### 1.1 项目概述

FileManager Plus 是一个功能强大的文件管理工具，主要用于批量文件重命名、格式转换、元数据抓取等操作。目前项目使用 JavaFX 作为前端框架，导致项目迁移和升级困难，尤其是在需要升级 Java 版本时（如升级到 Java 21）。

### 1.2 现有架构

**当前架构**：
- **前端**：JavaFX 21+
- **后端**：嵌入式 Java 逻辑
- **业务逻辑**：与 UI 耦合的策略模式实现
- **部署方式**：桌面应用

**主要模块**：
- `app/base`：核心接口和基础类
- `app/components`：核心组件（如 PipelineManager）
- `app/ui`：JavaFX UI 组件
- `model`：数据模型
- `strategy`：文件处理策略实现

### 1.3 存在的问题

1. **技术栈老化**：JavaFX 生态系统逐渐萎缩，社区活跃度低
2. **迁移困难**：每次 Java 版本升级都需要大量测试和调整
3. **部署复杂**：需要安装 Java 运行时环境
4. **跨平台问题**：在不同操作系统上表现不一致
5. **扩展性差**：业务逻辑与 UI 耦合，难以添加新功能
6. **用户体验局限**：无法提供 Web 访问方式

### 1.4 迁移目标

1. **解耦架构**：分离核心业务逻辑与 UI 层
2. **多端支持**：支持 Web、桌面等多种访问方式
3. **技术现代化**：采用现代前端框架和后端技术
4. **简化部署**：减少部署复杂度，支持容器化
5. **提高扩展性**：通过插件系统实现功能扩展
6. **保持兼容性**：支持现有功能和配置

## 2. 技术路线选择

### 2.1 候选技术路线

| 技术路线 | 前端 | 后端 | 优势 | 劣势 |
|---------|------|------|------|------|
| 1. Spring Boot + React | React 18+ | Spring Boot 3.2+ | 生态成熟，社区活跃 | 前后端分离，开发复杂度高 |
| 2. Spring Boot + Vue | Vue 3+ | Spring Boot 3.2+ | 轻量高效，学习曲线平缓 | 前后端分离，开发复杂度高 |
| 3. Spring Boot + Angular | Angular 17+ | Spring Boot 3.2+ | 企业级支持，功能完整 | 学习曲线陡峭，体积较大 |
| 4. Electron + 现有后端 | Electron | 现有 Java 逻辑 | 保持现有代码，开发成本低 | 仍为桌面应用，未解决核心问题 |
| 5. Flutter Web + 后端 API | Flutter 3.16+ | Spring Boot 3.2+ | 跨平台，代码复用率高 | Flutter Web 生态相对较新 |

### 2.2 最终选择

**选择技术路线 5：Flutter Web + 后端 API**

**选择理由**：
1. **跨平台能力**：Flutter 支持 Web、移动和桌面平台，一次开发多端运行
2. **代码复用**：核心业务逻辑可在多端共享
3. **现代化 UI**：提供流畅、美观的用户界面
4. **快速开发**：热重载功能加速开发迭代
5. **后端解耦**：通过 API 接口与后端分离，提高系统灵活性
6. **长期可维护性**：Google 支持，生态系统不断发展

**技术栈详情**：
- **前端**：Flutter 3.16+, Dart 3.2+
- **后端**：Spring Boot 3.2+, Java 21+
- **API**：RESTful + WebSocket
- **构建工具**：Maven 3.9+ (后端), Flutter CLI (前端)
- **部署**：Docker 容器化

## 3. 新架构设计

### 3.1 架构概述

**核心设计原则**：
- **分层架构**：清晰的职责分离
- **接口驱动**：基于接口的设计和依赖注入
- **插件化**：通过插件系统实现功能扩展
- **异步处理**：非阻塞的异步操作
- **实时通信**：WebSocket 实现实时更新

**架构层次**：
1. **客户端层**：Flutter Web、JavaFX 客户端
2. **API 层**：RESTful API、WebSocket 接口
3. **服务层**：业务逻辑服务、插件执行服务
4. **插件层**：文件处理插件
5. **共享域层**：核心实体和接口
6. **基础设施层**：文件系统、存储、日志

### 3.3 核心流程

**文件处理流程**：
1. 客户端选择文件和处理策略
2. 客户端调用后端 API 分析文件
3. 后端加载并执行相应插件
4. 插件生成变更记录
5. 后端返回变更记录给客户端
6. 客户端展示变更预览
7. 用户确认后，客户端调用后端执行变更
8. 后端执行文件操作并返回结果
9. WebSocket 实时推送执行状态

**插件管理流程**：
1. 后端启动时扫描并加载插件
2. 客户端获取可用插件列表
3. 客户端配置插件参数
4. 后端验证插件配置
5. 后端执行插件并返回结果

### 3.4 关键设计

#### 3.4.1 插件系统

- **核心接口**：`IPlugin` 定义插件标准行为
- **加载机制**：基于 Java SPI 机制动态加载
- **执行上下文**：`PluginContext` 提供执行环境
- **配置管理**：标准化的插件配置结构

#### 3.4.2 API 设计

- **RESTful API**：处理常规请求
- **WebSocket**：实现实时状态更新
- **认证授权**：基于 JWT 的安全机制
- **版本控制**：支持 API 版本管理

#### 3.4.3 客户端设计

- **JavaFX 客户端**：保持现有 UI，改造为使用 API
- **Flutter Web 客户端**：全新开发，提供现代化体验
- **共享服务**：客户端共享后端 API
- **并行使用**：两个客户端可同时使用
