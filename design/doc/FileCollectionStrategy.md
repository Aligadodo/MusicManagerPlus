# FileCollectionStrategy 设计文档

## 概述

**功能**: 文件智能归类策略，基于文件名相似度将文件/文件夹归类到合集文件夹中

**继承**: IAppStrategy

**设计模式**: 模块化设计、策略模式

## 核心职责

1. 基于文件名相似度进行文件聚类
2. 生成合集文件夹并移动文件
3. 支持关键词过滤
4. 支持添加到现有合集
5. 智能避免重复处理

## 核心组件

### 1. UI组件

#### 基础设置
- `slSimilarityThreshold`: 相似度阈值滑块（0.0-1.0）
- `txtCollectionSuffix`: 合集文件夹格式（如：【合集】）
- `cbTargetType`: 目标类型选择（文件夹/文件/全部）

#### 关键词过滤
- `txtMustContainKeywords`: 必须包含的关键词
- `txtMustNotContainKeywords`: 不能包含的关键词

### 2. 运行时参数

- `pThreshold`: 相似度阈值
- `pCollectionSuffix`: 合集文件夹后缀
- `pTargetType`: 目标类型
- `pMustContainKeywords`: 必须包含的关键词列表
- `pMustNotContainKeywords`: 不能包含的关键词列表

### 3. 模块化组件

- `FilenameNormalizer`: 文件名标准化
- `TextSimilarityCalculator`: 文本相似度计算
- `FileClusteringAlgorithm`: 文件聚类算法
- `CollectionDeterminationAlgorithm`: 合集判定算法

### 4. 状态跟踪

- `parentDirClusters`: 记录已处理的父目录和对应的文件集群

## 核心方法

### 1. analyze(ChangeRecord currentRecord, List<ChangeRecord> inputRecords, List<File> rootDirs)
**功能**: 分析文件并生成归类记录

**处理流程**:
1. 检查父目录是否已处理
2. 检查文件是否已在合集文件夹中
3. 检查文件是否本身就是合集文件夹
4. 获取父目录下所有符合条件的文件
5. 检查文件数量是否足够
6. 检查是否大部分文件已属于同一合集
7. 对文件进行聚类
8. 验证集群有效性
9. 尝试添加到现有合集
10. 创建新合集并移动文件

### 2. execute(ChangeRecord rec)
**功能**: 执行文件移动操作

**处理流程**:
1. 检查操作类型是否为COLLECT
2. 确保目标文件夹存在
3. 移动文件到目标位置

### 3. initializeComponents()
**功能**: 初始化模块化组件

**初始化流程**:
1. 创建FilenameNormalizer
2. 创建TextSimilarityCalculator
3. 创建FileClusteringAlgorithm
4. 创建CollectionDeterminationAlgorithm

### 4. addFilesToExistingCollections()
**功能**: 将文件添加到现有合集

**处理流程**:
1. 获取父目录下所有现有合集文件夹
2. 获取所有非合集文件
3. 检查每个文件是否应该添加到现有合集
4. 生成移动记录

## 设计要点

### 1. 模块化设计

**组件职责**:
- `FilenameNormalizer`: 标准化文件名
- `TextSimilarityCalculator`: 计算文本相似度
- `FileClusteringAlgorithm`: 执行文件聚类
- `CollectionDeterminationAlgorithm`: 判定合集有效性

**优势**:
- 职责清晰
- 易于测试
- 便于维护和扩展

### 2. 智能聚类算法

**聚类流程**:
1. 标准化文件名
2. 计算文件名相似度
3. 基于相似度阈值进行聚类
4. 生成合集名称

**合集名称生成**:
- 基于最长公共前缀
- 清理不必要的字符
- 应用合集后缀

### 3. 关键词过滤

**必须包含关键词**:
- 文件名必须包含指定关键词
- 支持多个关键词（逗号分隔）
- 提高归类准确性

**不能包含关键词**:
- 文件名不能包含指定关键词
- 过滤掉不需要的文件
- 避免错误归类

### 4. 避免重复处理

**检查机制**:
- 检查父目录是否已处理
- 检查文件是否已在合集文件夹中
- 检查文件是否本身就是合集文件夹
- 检查是否大部分文件已属于同一合集

**优势**:
- 提高处理效率
- 避免重复操作
- 防止无限循环

### 5. 添加到现有合集

**判断条件**:
- 文件名与合集名称相似度 >= 阈值 * 0.9
- 文件与合集内文件平均相似度 >= 阈值 * 0.8
- 文件符合关键词过滤条件

**处理流程**:
1. 遍历所有现有合集
2. 检查文件是否应该添加
3. 生成移动记录
4. 一个文件只添加到一个合集

## 注意事项

### 1. 相似度阈值

**推荐值**:
- 0.9: 严格聚类，适合命名规范的文件
- 0.8: 中等聚类，适合一般情况
- 0.7: 宽松聚类，适合命名不规范的文件

**调整建议**:
- 根据实际文件命名情况调整
- 先在小范围测试
- 逐步调整到最佳值

### 2. 文件数量限制

**最小数量**: 2个文件

**原因**:
- 单个文件无法形成合集
- 避免创建不必要的合集文件夹

### 3. 大部分文件已属于同一合集

**判断标准**: 超过80%的文件属于同一合集

**处理方式**: 跳过处理，避免破坏现有结构

### 4. 合集文件夹识别

**识别规则**:
- 文件夹名称包含合集后缀
- 文件夹符合关键词过滤条件

**避免处理**:
- 已在合集文件夹中的文件
- 本身就是合集文件夹的文件

### 5. 文件移动安全

**移动方式**:
- 使用Files.move()
- 支持REPLACE_EXISTING选项
- 直接抛出异常让上层处理

**目录创建**:
- 自动创建目标文件夹
- 确保路径存在

## 常见问题

### Q1: 为什么某些文件没有被归类？

**可能原因**:
1. 文件数量不足2个
2. 相似度低于阈值
3. 不符合关键词过滤条件
4. 已在合集文件夹中
5. 大部分文件已属于同一合集

**解决方案**:
1. 降低相似度阈值
2. 调整关键词过滤条件
3. 检查文件命名规范性

### Q2: 如何提高归类准确性？

**优化建议**:
1. 调整相似度阈值
2. 设置合适的关键词过滤
3. 规范文件命名
4. 使用合集后缀标识

### Q3: 如何避免重复归类？

**解决方案**:
1. 系统自动检查父目录是否已处理
2. 检查文件是否已在合集文件夹中
3. 检查是否大部分文件已属于同一合集

### Q4: 如何处理现有合集？

**处理方式**:
1. 系统自动识别现有合集
2. 尝试将文件添加到现有合集
3. 相似度要求：阈值 * 0.9
4. 与合集内文件平均相似度：阈值 * 0.8

## 最佳实践

### 1. 参数配置

**严格归类**:
- 相似度阈值：0.9
- 合集后缀：【合集】
- 必须包含：CD, 系列
- 不能包含：下载, Album

**宽松归类**:
- 相似度阈值：0.7
- 合集后缀：【合集】
- 必须包含：（空）
- 不能包含：下载

### 2. 文件命名规范

**推荐格式**:
- 艺术家 - 专辑 - 序号
- 专辑名称 CD1
- 专辑名称 Vol.1

**避免**:
- 过多的特殊字符
- 不一致的命名格式
- 缺少关键信息

### 3. 处理流程

**推荐顺序**:
1. 先整理文件命名
2. 设置合适的参数
3. 小范围测试
4. 批量处理
5. 检查结果

### 4. 性能优化

**大批量处理**:
- 分批处理
- 监控处理进度
- 定期检查结果

**避免重复**:
- 系统自动跟踪处理状态
- 避免重复处理同一目录

FileCollectionStrategy提供了完整的文件归类功能，具有以下特点：

1. **模块化设计**: 职责清晰，易于维护和扩展
2. **智能聚类**: 基于相似度自动归类文件
3. **关键词过滤**: 提高归类准确性
4. **避免重复**: 智能跟踪处理状态
5. **灵活配置**: 丰富的参数配置选项
6. **用户友好**: 直观的配置界面

通过模块化设计，FileCollectionStrategy将复杂的归类逻辑分解为多个独立的组件，每个组件职责清晰，便于测试和维护。同时，系统提供了丰富的配置选项，用户可以根据实际情况调整参数，获得最佳的归类效果。
