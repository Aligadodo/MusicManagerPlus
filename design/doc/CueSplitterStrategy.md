# CueSplitterStrategy 设计文档

## 概述

**功能**: CUE分轨策略，解析CUE索引文件，将整轨音频无损切割为单曲

**继承**: AbstractFfmpegStrategy

**设计模式**: 继承扩展模式

**版本**: 专业版

## 核心职责

1. 解析CUE文件并提取音轨信息
2. 智能定位音频源文件
3. 基于时间戳精确切割音频
4. 写入音轨元数据
5. 切分后处理（删除、归档等）
6. 避免文件锁问题

## 核心组件

### 1. 新增UI组件

#### 切分完成后执行选项
- `cbAfterSplitAction`: 切分后操作选择

- `pEnableArchive`: 是否启用归档
- `pArchiveDir`: 归档目录路径

### 3. 状态跟踪

- `cueTrackProcessingStatus`: 跟踪每个CUE文件的音轨处理状态

## 核心方法

### 1. analyze(ChangeRecord rec, List<ChangeRecord> inputRecords, List<File> rootDirs)
**功能**: 分析CUE文件并生成切分记录

**处理流程**:
1. 检查是否为CUE文件
2. 解析CUE文件
3. 检查是否已分轨（避免重复切分）
4. 定位音频源文件
5. 遍历音轨生成切分记录
6. 初始化音轨处理状态

**关键逻辑**:
```java
// 检查是否已分轨
if (cueSheet.getCountFiles() == cueSheet.getTracks().size()) {
    log("已切分的分轨文件，无需重新切分");
    return Collections.emptyList();
}

// 定位音频源文件
File sourceAudio = CueParserUtil.locateAudioFile(cueFile, cueSheet.getAlbumFileName());
```

### 2. execute(ChangeRecord rec)
**功能**: 执行音轨切分

**处理流程**:
1. 检查操作类型是否为SPLIT
2. 调用父类execute方法执行切分
3. 标记当前音轨为已完成
4. 检查是否所有音轨都已完成
5. 执行切分后操作

### 3. afterSplitProcess(String cueFilePath, String audioFilePath)
**功能**: 切分完成后执行选择的操作

**操作类型**:
1. **什么都不做**: 保持原始文件不变
2. **删除原始文件**: 删除CUE文件和音频文件
3. **归档原始文件**: 移动到归档目录

### 4. deleteOriginalFiles(String cueFilePath, String audioFilePath)
**功能**: 删除原始文件

**处理流程**:
1. 删除CUE文件
2. 删除音频文件
3. 清理处理状态记录

### 5. archiveOriginalFiles(String cueFilePath, String audioFilePath)
**功能**: 归档原始文件

**处理流程**:
1. 确保归档目录存在
2. 归档CUE文件
3. 归档音频文件
4. 归档其他相关文件（非音轨文件）
5. 清理处理状态记录

### 6. 状态跟踪方法

**initializeCueTracks**: 初始化CUE文件的音轨列表
**markTrackAsCompleted**: 标记音轨为已完成
**isAllTracksCompleted**: 检查所有音轨是否都已完成

## 设计要点

### 1. 智能定位音频源

**定位策略**:
1. 解析CUE文件中的FILE命令
2. 在同目录下查找对应的音频文件
3. 支持相对路径和绝对路径
4. 支持多种音频格式

### 2. 精确时间切割

**时间参数**:
- `start`: 起始时间（毫秒）
- `duration`: 持续时间（毫秒）

**FFmpeg参数**:
```java
builder.setStartOffset(startMillis, TimeUnit.MILLISECONDS);
outputBuilder.setDuration(durationMillis, TimeUnit.MILLISECONDS);
```

### 3. 元数据写入

**元数据字段**:
- title: 音轨标题
- artist: 演唱者
- album: 专辑名称
- track: 音轨编号

**写入方式**:
- 从CUE文件提取元数据
- 通过FFmpeg参数写入

### 4. 避免文件锁

**问题**: 同一个音频文件被多个音轨同时访问会导致文件锁

**解决方案**:
- 跟踪每个CUE文件的音轨处理状态
- 同一个音轨不会同时执行
- 分成多轮任务逐个完成切分

### 5. 性能优化

**缓存和镜像**:
- 缓存目录：缓解IO瓶颈
- 镜像目录：挂载到SSD盘下
- 处理效率提升5-10倍

**应用场景**:
- 音频存储在机械盘
- 需要大批量切分
- 对处理速度有要求

## 注意事项

### 1. CUE文件格式

**支持的格式**:
- 标准CUE格式
- UTF-8编码
- 多种音频格式引用

**不支持**:
- 非标准CUE格式
- 损坏的CUE文件
- 编码错误的CUE文件

### 2. 音频源定位

**定位规则**:
1. 优先使用CUE文件中的路径
2. 在同目录下查找
3. 支持相对路径和绝对路径
4. 大小写不敏感

**失败处理**:
- 找不到音频源时跳过该CUE文件
- 记录错误日志

### 3. 文件存在性检查

**检查参数**:
- 大小写不敏感
- 简体中文匹配
- 去除首尾空格

**检查逻辑**:
1. 检查目标路径下是否存在同名文件
2. 如果启用doubleCheck，检查双重路径
3. 如果存在且未启用覆盖，跳过处理

### 4. 切分后处理

**删除操作**:
- 永久删除，无法恢复
- 需要用户确认
- 建议先归档再删除

**归档操作**:
- 移动到指定目录
- 保留原始文件
- 归档相关文件（非音轨文件）

### 5. 性能考虑

**机械盘优化**:
- 使用缓存目录
- 使用镜像目录
- 挂载到SSD盘下

**大批量处理**:
- 分批处理
- 监控磁盘空间
- 定期清理临时文件

## 常见问题

### Q1: 为什么某些CUE文件被跳过？

**原因**:
1. CUE文件解析失败
2. 找不到音频源文件
3. 已经是分轨文件
4. 目标文件已存在且未启用覆盖

**解决方案**:
1. 检查CUE文件格式是否正确
2. 确保音频源文件存在
3. 检查覆盖设置

### Q2: 切分速度慢怎么办？

**优化建议**:
1. 启用缓存目录
2. 使用镜像目录（挂载到SSD）
3. 减少同时处理的CUE文件数量
4. 检查磁盘IO性能

### Q3: 如何避免文件锁问题？

**解决方案**:
1. 系统自动跟踪音轨处理状态
2. 同一个音轨不会同时执行
3. 分成多轮任务逐个完成
4. 无需手动干预

### Q4: 切分后如何处理原始文件？

**推荐流程**:
1. 先归档原始文件
2. 检查切分结果
3. 确认无误后再删除
4. 避免直接删除

## 总结

CueSplitterStrategy提供了完整的CUE分轨功能，具有以下特点：

1. **智能定位**: 自动定位音频源文件
2. **精确切割**: 基于时间戳精确切割
3. **元数据保留**: 完整保留音轨元数据
4. **避免文件锁**: 智能跟踪处理状态
5. **灵活处理**: 支持多种切分后操作
6. **性能优化**: 支持缓存和镜像，提升5-10倍效率

通过继承AbstractFfmpegStrategy，CueSplitterStrategy获得了强大的FFmpeg集成能力，同时添加了CUE特定的功能，为用户提供了专业级的CD分轨体验。
