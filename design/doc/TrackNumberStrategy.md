# TrackNumberStrategy 设计文档

## 概述

**功能**: 音轨编号策略，为音频文件添加或修改音轨编号

**继承**: IAppStrategy

**设计模式**: 策略模式

## 核心职责

1. 为音频文件添加音轨编号
2. 支持多种编号模式
3. 支持双位补零
4. 支持自定义分隔符
5. 支持文本列表匹配

## 核心组件

### 1. UI组件

#### 排序模式
- `cbMode`: 排序模式选择
  - 元数据排序（按音轨编号）
  - 文本列表匹配（.txt/.nfo）
  - CUE文件匹配（.cue）
  - 自定义顺序
  - 默认排序（按文件名/拼音）

#### 编号选项
- `chkPadZero`: 双位补零（如01, 02）
- `txtSeparator`: 自定义分隔符（默认：. ）
- `spStartNumber`: 起始编号（默认：1）
- `cbNumberFormat`: 编号格式（1, 01, 001）

#### 高级选项
- `chkUpdateMetadata`: 更新元数据中的音轨编号
- `chkPreserveOriginal`: 保留原始文件
- `chkGroupByDirectory`: 按目录分组编号

### 2. 运行时参数

- `pMode`: 编号模式
- `pPadZero`: 是否补零
- `pSeparator`: 分隔符

## 核心方法

### 1. analyze(ChangeRecord rec, List<ChangeRecord> inputRecords, List<File> rootDirs)
**功能**: 分析文件并生成编号记录

**处理流程**:
1. 检查文件是否为音频文件
2. 根据模式生成编号
3. 生成新的文件名
4. 检查目标文件是否存在
5. 生成ChangeRecord

**编号模式**:
- **默认排序**: 按文件名/拼音排序后编号
- **文本列表匹配**: 从.txt/.nfo文件中读取编号信息

### 2. execute(ChangeRecord rec)
**功能**: 执行文件重命名操作

**处理流程**:
1. 检查操作类型是否为RENAME
2. 重命名文件
3. 更新元数据中的音轨编号

## 设计要点

### 1. 编号模式

**默认排序模式**:
- 按文件名排序
- 按拼音排序
- 顺序编号（1, 2, 3...）

**文本列表匹配模式**:
- 从.txt文件读取编号信息
- 从.nfo文件读取编号信息
- 支持自定义格式

### 2. 双位补零

**作用**: 确保编号格式统一

**示例**:
- 不补零：1, 2, 3, 10, 11
- 补零：01, 02, 03, 10, 11

### 3. 自定义分隔符

**默认**: . （点+空格）

**示例**:
- . （点+空格）：01. 歌曲名称
- - （短横线）：01-歌曲名称
- _ （下划线）：01_歌曲名称

### 4. 元数据更新

**更新字段**:
- 文件名
- 音轨编号（Track）

**更新方式**:
- 重命名文件
- 更新音频文件的元数据

## 注意事项

### 1. 文件类型

**支持**: 音频文件（MP3, FLAC, WAV等）

**不支持**: 非音频文件

### 2. 文本列表格式

**.txt文件格式**:
```
01. 第一首歌
02. 第二首歌
03. 第三首歌
```

**.nfo文件格式**:
```
<track>01</track><title>第一首歌</title>
<track>02</track><title>第二首歌</title>
```

### 3. 文件名冲突

**处理方式**:
- 检查目标文件是否存在
- 如果存在且未启用覆盖，跳过处理
- 如果启用覆盖，覆盖现有文件

### 4. 编号顺序

**默认排序**:
- 按文件名字母顺序
- 按拼音顺序
- 保持原始顺序

**文本列表匹配**:
- 按文本文件中的顺序
- 支持自定义编号

### 5. 元数据兼容性

**支持格式**:
- MP3（ID3标签）
- FLAC（Vorbis注释）
- WAV（INFO标签）

**不支持**:
- 某些特殊格式
- 损坏的元数据

## 常见问题

### Q1: 为什么某些文件没有被编号？

**可能原因**:
1. 不是音频文件
2. 目标文件已存在且未启用覆盖
3. 文本列表文件不存在或格式错误

**解决方案**:
1. 检查文件类型
2. 启用覆盖选项
3. 检查文本列表文件格式

### Q2: 如何自定义编号格式？

**解决方案**:
1. 调整分隔符设置
2. 启用或禁用双位补零
3. 使用文本列表匹配模式

### Q3: 如何批量编号？

**步骤**:
1. 选择源目录
2. 配置编号参数
3. 选择编号模式
4. 执行批量编号

### Q4: 编号后如何恢复？

**解决方案**:
1. 保留原始文件名记录
2. 使用备份恢复
3. 手动重命名恢复

## 最佳实践

### 1. 编号模式选择

**默认排序**:
- 文件名有规律
- 需要按顺序编号
- 批量处理

**文本列表匹配**:
- 有现成的曲目列表
- 需要自定义编号
- 特殊编号需求

### 2. 参数配置

**标准编号**:
- 模式：默认排序
- 补零：启用
- 分隔符：. （点+空格）

**自定义编号**:
- 模式：文本列表匹配
- 补零：根据需要
- 分隔符：根据需要

### 3. 处理流程

**推荐顺序**:
1. 使用CueSplitterStrategy分轨
2. 使用AudioConverterStrategy转换
3. 使用TrackNumberStrategy编号
4. 使用MetadataScraperStrategy抓取元数据

### 4. 文件管理

**避免冲突**:
- 默认不勾选覆盖选项
- 检查目标文件是否存在
- 使用文件存在性检查

**备份重要**:
- 编号前备份原始文件
- 保留原始文件名记录
- 便于恢复和回退

## 优化建议

### 1. 编号模式优化

**当前实现**: 默认排序、文本列表匹配

**优化方向**:
- 支持自定义排序规则
- 支持正则表达式匹配
- 支持多级编号

### 2. 文本列表优化

**当前实现**: 支持.txt和.nfo文件

**优化方向**:
- 支持更多格式（CSV, JSON等）
- 支持自定义解析规则

### 3. 元数据处理优化

**当前实现**: 更新文件名和音轨编号

**优化方向**:
- 支持更多元数据字段
- 支持自定义元数据映射
- 支持元数据模板

## 总结

TrackNumberStrategy提供了完整的音轨编号功能，具有以下特点：

1. **模式灵活**: 支持元数据排序、文本列表匹配、CUE文件匹配、自定义顺序和默认排序
2. **格式可配**: 支持多种编号格式、双位补零和自定义分隔符
3. **元数据同步**: 同步更新文件名和音轨编号
4. **批量处理**: 支持批量编号操作
5. **易于使用**: 直观的配置界面
6. **安全可靠**: 支持文件保留和备份

通过TrackNumberStrategy，用户可以快速为音频文件添加规范的音轨编号，提高音乐文件的组织性和可读性。
