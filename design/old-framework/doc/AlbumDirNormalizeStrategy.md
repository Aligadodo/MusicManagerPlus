# AlbumDirNormalizeStrategy 设计文档

## 概述

**功能**: 专辑目录规范化策略，根据音频文件元数据规范化专辑文件夹名称

**继承**: IAppStrategy

**设计模式**: 策略模式

## 核心职责

1. 分析专辑目录中的音频文件元数据
2. 提取共识元数据（艺术家、专辑、年份、流派等）
3. 根据模板生成规范化的目录名称
4. 重命名专辑目录
5. 支持多种命名模板
6. 支持元数据验证

## 核心组件

### 1. UI组件

#### 命名模板
- `cbTemplate`: 命名模板选择
  - 艺术家 - 专辑
  - 艺术家 - 专辑 [年份]

  - 专辑 [年份] - 艺术家

- `chkKeepOriginalStructure`: 保留原始目录结构

### 2. 运行时参数

- `pTemplate`: 命名模板
- `pUseConsensus`: 是否使用共识元数据
- `pValidateMetadata`: 是否验证元数据
- `pCustomTemplate`: 自定义模板
- `pBackupOriginal`: 是否备份
- `pUpdateMetadata`: 是否更新元数据
- `pKeepOriginalStructure`: 是否保留结构

## 核心方法

### 1. analyze(ChangeRecord rec, List<ChangeRecord> inputRecords, List<File> rootDirs)
**功能**: 分析目录并生成规范化记录

**处理流程**:
1. 检查是否为目录
2. 收集目录中的所有音频文件
3. 提取每个文件的元数据
4. 计算共识元数据
5. 根据模板生成新目录名
6. 验证元数据完整性（如果启用）
7. 生成ChangeRecord

**共识元数据计算**:
- 统计每个字段的频率
- 选择出现频率最高的值
- 处理艺术家名称变体（如"王菲"、"Faye Wong"）

### 2. execute(ChangeRecord rec)
**功能**: 执行目录重命名操作

**处理流程**:
1. 检查操作类型是否为ALBUM_RENAME
2. 备份原始目录（如果启用）
3. 重命名目录
4. 更新文件元数据（如果启用）
5. 清理备份（可选）

## 设计要点

### 1. 命名模板

**预设模板**:

1. **艺术家 - 专辑**
   - 示例：王菲 - 王菲
   - 适用于：标准专辑

2. **艺术家 - 专辑 [年份]**
   - 示例：王菲 - 王菲 [1992]
   - 适用于：需要年份信息的专辑

3. **专辑 - 艺术家**
   - 示例：天空 - 王菲
   - 适用于：以专辑名为主的命名

4. **专辑 [年份] - 艺术家**
   - 示例：天空 [1994] - 王菲
   - 适用于：需要年份信息的专辑

5. **自定义模板**
   - 支持占位符：{artist}, {album}, {year}, {genre}
   - 示例：{artist} - {album} ({year})

### 2. 共识元数据

**计算方法**:
- 统计每个字段的值频率
- 选择频率最高的值
- 处理常见变体

**字段**:
- 艺术家（Artist）
- 专辑（Album）
- 年份（Year）
- 流派（Genre）

**变体处理**:
- "王菲" vs "Faye Wong" → 统一为"王菲"
- "The Beatles" vs "Beatles" → 统一为"The Beatles"

### 3. 元数据验证

**验证规则**:
- 艺术家不能为空或"Unknown Artist"
- 专辑不能为空或"Unknown Album"
- 年份格式正确（4位数字）
- 流派不为空

**处理方式**:
- 验证失败：跳过该目录
- 验证成功：继续处理

### 4. 备份机制

**备份方式**:
- 创建原始目录的副本
- 添加时间戳后缀
- 位置：同级目录

**备份命名**:
- 原始目录名_backup_YYYYMMDD_HHMMSS

**清理策略**:
- 处理成功后可选择删除备份
- 处理失败时保留备份

### 5. 元数据更新

**更新字段**:
- 艺术家（Artist）
- 专辑（Album）
- 年份（Year）
- 流派（Genre）

**更新方式**:
- 使用共识元数据
- 保留其他元数据字段
- 支持选择性更新

## 注意事项

### 1. 目录结构

**要求**:
- 目录中必须包含音频文件
- 音频文件必须有元数据
- 建议目录只包含一个专辑的文件

**不支持**:
- 混合多个专辑的目录
- 没有音频文件的目录
- 元数据缺失的目录

### 2. 文件类型

**支持**: 音频文件（MP3, FLAC, WAV, AAC等）

**不支持**: 非音频文件

### 3. 元数据质量

**影响因素**:
- 元数据来源
- 元数据编辑工具
- 文件来源

**建议**:
- 使用MetadataScraperStrategy补充元数据
- 手动检查关键元数据
- 使用一致的元数据格式

### 4. 命名冲突

**处理方式**:
- 检查目标目录是否存在
- 如果存在且未启用覆盖，跳过处理
- 如果启用覆盖，覆盖现有目录

**风险**:
- 可能丢失现有目录内容
- 建议先备份
- 确认无误后再覆盖

### 5. 路径长度

**限制**:
- Windows：260字符
- Linux：4096字符

**建议**:
- 使用简洁的命名模板
- 避免过长的艺术家或专辑名
- 使用缩写或简称

## 常见问题

### Q1: 为什么某些目录没有被规范化？

**可能原因**:
1. 目录中没有音频文件
2. 音频文件元数据不完整
3. 元数据验证失败
4. 目标目录已存在且未启用覆盖

**解决方案**:
1. 检查目录内容
2. 使用MetadataScraperStrategy补充元数据
3. 禁用元数据验证
4. 启用覆盖选项

### Q2: 如何自定义命名模板？

**解决方案**:
1. 选择"自定义模板"
2. 输入自定义模板
3. 使用占位符：{artist}, {album}, {year}, {genre}

**示例**:
- {artist} - {album} ({year})
- [{year}] {album} - {artist}
- {album} / {artist} / {genre}

### Q3: 共识元数据不准确怎么办？

**解决方案**:
1. 检查音频文件的元数据
2. 使用MetadataScraperStrategy更新元数据
3. 手动修正关键元数据
4. 禁用共识元数据，手动指定

### Q4: 如何批量规范化多个专辑目录？

**步骤**:
1. 选择包含多个专辑的根目录
2. 配置规范化参数
3. 选择命名模板
4. 执行批量规范化
