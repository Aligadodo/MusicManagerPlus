# 迭代文档维护指南

## 概述

本文档定义了在完成功能迭代后，维护项目关键文档的标准流程和规范。通过系统化的文档维护，确保项目知识得以积累、传承和复用，提高团队协作效率和项目质量。

## 文档维护目标

1. **知识积累**: 记录设计思路、实现细节、优化经验
2. **经验传承**: 便于团队成员快速了解项目历史和技术细节
3. **质量保障**: 通过文档审查发现设计问题和改进空间
4. **效率提升**: 避免重复踩坑，加速后续开发

## 文档目录结构

```
design/
├── doc/           # 策略类说明文档
├── review/        # 迭代过程总结
├── skill/         # 实践技巧和最佳实践
├── problem/       # 项目问题记录
└── command/       # 命令使用说明
```

## 文档维护清单

### 1. 策略类文档维护 (design/doc/)

**触发条件**: 策略实现类有更新或新增

**维护内容**:
- 功能特点描述
- 设计思路说明
- 核心算法逻辑
- 配置参数说明
- 待优化项列表
- 使用示例

**文档命名规范**: `{StrategyName}.md`

**示例**: `AudioConverterStrategy.md`, `MetadataScraperStrategy.md`

**文档模板**:
```markdown
# {策略名称}

## 概述
简要描述策略的功能和用途

## 功能特点
- 特点1
- 特点2

## 设计思路
详细说明策略的设计思路和实现原理

## 核心逻辑
关键代码片段和算法说明

## 配置参数
| 参数 | 类型 | 说明 | 默认值 |
|------|------|------|--------|
| param1 | String | 参数说明 | 默认值 |

## 待优化项
- [ ] 优化项1
- [ ] 优化项2

## 使用示例
代码示例

## 相关文档
- [相关策略文档](xxx.md)
```

## 文档维护流程

### 标准维护流程

```
1. 完成功能迭代
   ↓
2. 检查文档维护清单
   ↓
3. 识别需要更新的文档
   ↓
4. 按照模板创建或更新文档
   ↓
5. 审查文档质量
   ↓
6. 提交文档更新
```

### 详细步骤

#### 步骤1: 完成功能迭代
确保功能已经实现、测试通过并达到预期目标

#### 步骤2: 检查文档维护清单
对照文档维护清单，逐项检查是否需要更新

#### 步骤3: 识别需要更新的文档
根据迭代内容，确定需要维护的文档类型和具体文档

#### 步骤4: 按照模板创建或更新文档
- 查看同类文档的格式和风格
- 使用对应的文档模板
- 确保内容完整、准确、清晰

#### 步骤5: 审查文档质量
- 检查文档格式是否规范
- 确保内容准确无误
- 验证链接和引用是否有效
- 确认代码示例可运行

#### 步骤6: 提交文档更新
将文档更新纳入版本控制，提交时使用清晰的提交信息

## 文档质量标准

### 内容质量
- **准确性**: 内容必须准确无误
- **完整性**: 信息必须完整全面
- **清晰性**: 表达必须清晰易懂
- **实用性**: 内容必须具有实用价值

### 格式规范
- **结构清晰**: 使用合理的标题层级
- **格式统一**: 遵循统一的格式规范
- **代码规范**: 代码示例符合项目规范
- **链接有效**: 确保所有链接可访问

### 维护要求
- **及时更新**: 文档必须及时更新
- **版本管理**: 纳入版本控制
- **定期审查**: 定期审查文档有效性
- **持续改进**: 持续改进文档质量

## 最佳实践

### 1. 及时性
- 完成迭代后立即维护文档
- 避免延迟导致信息遗漏
- 保持文档与代码同步

### 2. 准确性
- 确保所有信息准确无误
- 验证代码示例可运行
- 检查链接和引用有效

### 3. 完整性
- 按照模板填写所有必要信息
- 不遗漏重要的细节
- 提供足够的上下文

### 4. 清晰性
- 使用清晰简洁的语言
- 避免模糊不清的表达
- 提供具体的示例

### 5. 实用性
- 内容必须具有实用价值
- 提供可操作的指导
- 避免空洞的理论

### 6. 一致性
- 遵循统一的格式规范
- 保持术语一致
- 使用统一的命名规范

## 常见问题

### Q1: 什么时候需要维护文档？
**A**: 每次完成功能迭代后，都需要对照文档维护清单，检查是否需要更新相关文档。

### Q2: 如何确定需要维护哪些文档？
**A**: 根据迭代内容和触发条件，逐项检查文档维护清单，确定需要维护的文档类型和具体文档。

### Q3: 文档模板是强制的吗？
**A**: 不是强制的，但强烈建议使用文档模板，以确保文档格式统一、内容完整。

### Q4: 如何保证文档质量？
**A**: 使用文档审查检查清单，逐项检查文档质量，确保内容准确、完整、清晰、实用。

### Q5: 文档更新需要代码审查吗？
**A**: 建议文档更新也经过审查，特别是重要的策略文档和README文档。

### Q6: 如何处理过时的文档？
**A**: 定期审查文档有效性，及时更新或删除过时的文档，保持文档的时效性。
