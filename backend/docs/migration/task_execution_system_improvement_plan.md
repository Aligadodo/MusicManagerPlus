# 任务执行系统改造方案

## 问题分析

### 1. 时间戳记录问题
- **现状**：部分任务阶段的时间戳显示为1970年或缺失
- **原因**：时间戳设置逻辑存在，但在某些异常情况下可能未正确设置
- **影响**：无法准确追踪各阶段的执行时间和耗时

### 2. 任务操作选项不足
- **现状**：操作按钮固定，缺乏智能判断
- **需求**：根据任务状态和阶段动态显示操作选项
- **影响**：用户体验不够友好，操作不够灵活

### 3. 任务阶段重新执行能力缺失
- **现状**：只能从当前状态继续，无法从任意阶段重新开始
- **需求**：支持重新扫描、重新分析、重新执行
- **影响**：调试和问题排查困难

### 4. 配置快照管理不完善
- **现状**：配置快照信息展示不完整
- **需求**：每个任务关联固定快照，支持JSON展示和复制
- **影响**：无法追溯任务使用的具体配置

## 改造方案

### 方案一：时间戳记录完善

#### 1.1 数据库层面改造
- **修改表结构**：确保所有时间戳字段有默认值
- **添加索引**：为时间戳字段添加索引以优化查询
- **数据修复**：提供脚本修复历史数据中的时间戳

#### 1.2 代码层面改造
- **异常处理**：在所有阶段开始和结束时确保时间戳设置
- **状态检查**：在任务加载时验证时间戳完整性
- **日志记录**：增加时间戳设置的调试日志

#### 1.3 实施步骤
1. 检查并修复所有阶段的时间戳设置逻辑
2. 添加时间戳验证和修复方法
3. 更新数据库表结构（如需要）
4. 提供历史数据修复脚本

### 方案二：任务操作选项优化

#### 2.1 操作逻辑设计
```
任务状态 → 可用操作
CREATED → 扫描
SCANNING → 取消
SCANNED → 预览
PREVIEWING → 取消
PREVIEWED → 执行、重新扫描、重新分析
EXECUTING → 取消
COMPLETED → 重新扫描、重新分析、重新执行
FAILED → 重试、重新扫描、重新分析、重新执行
CANCELLED → 重新扫描、删除
```

#### 2.2 重试逻辑设计
- **扫描阶段失败**：重新执行完整扫描
- **预览阶段失败**：重新执行完整预览
- **执行阶段失败**：只重试失败的记录（部分重试）
- **整体失败**：根据失败阶段重新执行对应阶段

#### 2.3 实施步骤
1. 设计操作按钮的显示逻辑
2. 实现智能操作判断方法
3. 添加各阶段的重试/重新执行API
4. 更新前端UI，支持动态操作按钮

### 方案三：任务阶段重新执行能力

#### 3.1 后端API设计
```
POST /api/tasks/{taskId}/restart/scan
POST /api/tasks/{taskId}/restart/preview
POST /api/tasks/{taskId}/restart/execution
```

#### 3.2 重新执行逻辑
- **重新扫描**：清空扫描数据，重新开始扫描
- **重新分析**：保留扫描数据，重新开始预览
- **重新执行**：保留扫描和预览数据，重新开始执行

#### 3.3 状态管理
- 重新执行时重置对应阶段的状态
- 保留已完成阶段的数据
- 更新任务整体状态

#### 3.4 实施步骤
1. 实现各阶段的重新执行方法
2. 添加对应的REST API端点
3. 实现状态重置和数据保留逻辑
4. 前端添加重新执行操作按钮

### 方案四：配置快照管理完善

#### 4.1 数据模型改造
- **任务表**：添加config_snapshot_id字段
- **快照表**：确保快照版本管理
- **关联关系**：建立任务与快照的强关联

#### 4.2 快照展示优化
- **JSON格式化**：自动格式化大JSON
- **折叠显示**：默认折叠，支持展开查看
- **复制功能**：支持一键复制配置
- **语法高亮**：JSON语法高亮显示

#### 4.3 实施步骤
1. 修改任务表结构，添加快照关联
2. 实现快照版本管理逻辑
3. 前端实现JSON格式化和折叠组件
4. 添加复制和导出功能

## 技术要点

### 1. 时间戳处理
- 使用System.currentTimeMillis()确保时间戳准确性
- 在异常情况下也要设置结束时间
- 添加时间戳完整性验证

### 2. 操作逻辑
- 基于任务状态和阶段判断可用操作
- 提供清晰的操作提示
- 支持操作确认和撤销

### 3. 状态管理
- 明确各阶段的状态转换
- 保留已完成阶段的数据
- 提供状态回滚能力

### 4. 用户体验
- 操作按钮动态显示
- 提供操作反馈
- 支持操作历史查看

## 预期效果

1. **时间戳完整**：所有阶段都有准确的开始和结束时间
2. **操作灵活**：根据任务状态提供合适的操作选项
3. **调试便捷**：可以从任意阶段重新执行任务
4. **配置透明**：清楚看到任务使用的配置快照

## 风险评估

1. **数据一致性**：重新执行可能影响数据一致性
2. **状态同步**：多阶段操作需要确保状态同步
3. **性能影响**：频繁的状态更新可能影响性能
4. **用户体验**：复杂的操作逻辑可能影响用户体验

## 缓解措施

1. **事务处理**：关键操作使用事务确保数据一致性
2. **状态锁**：防止并发操作导致状态混乱
3. **性能优化**：批量更新减少数据库操作
4. **用户引导**：提供清晰的操作说明和提示
