# 策略测试用例设计文档

## 测试用例设计原则

### 1. 可读性
- 每个测试方法都有清晰的JavaDoc注释
- 注释包含：测试场景、目的、测试数据、断言
- 测试方法名称清晰表达测试意图
- 使用描述性的断言消息

### 2. 覆盖率
- **功能覆盖**：覆盖策略的所有主要功能分支
- **场景覆盖**：包含正常场景、边界场景、异常场景
- **方法覆盖**：覆盖策略的核心方法（analyze、execute等）
- **配置覆盖**：验证所有配置字段的有效性

### 3. 可维护性
- 使用测试基类（StrategyTestBase）提供通用测试工具
- 使用辅助方法简化测试代码（createTestFile、assertChangeRecord等）
- 测试数据与测试逻辑分离
- 每个测试方法独立运行，不依赖其他测试

### 4. 关键断言
- **状态断言**：验证策略执行后的状态（changed、status）
- **数据断言**：验证变更记录的数量和内容
- **文件断言**：验证文件系统的变化（文件存在/不存在）
- **配置断言**：验证配置字段的完整性

## 测试用例模板

```java
/**
 * 测试场景N：场景描述
 * 
 * 目的：测试目的说明
 * 测试数据：
 * - 测试数据1
 * - 测试数据2
 * 断言：
 * - 断言1
 * - 断言2
 */
@Test
public void testScenarioName() throws Exception {
    // 1. 准备测试数据
    File testFile = createTestFile("test.txt", "content");
    
    // 2. 配置策略参数
    StrategyConfigDTO config = new StrategyConfigDTO();
    config.setConfigValues(new HashMap<>());
    config.getConfigValues().put("param1", "value1");
    
    // 3. 执行分析阶段
    List<String> filePaths = new ArrayList<>();
    filePaths.add(testFile.getAbsolutePath());
    List<ChangeRecord> records = strategyService.analyzeFiles("strategy-id", filePaths, config);
    
    // 4. 断言分析结果
    assertNotNull(records, "变更记录不应为空");
    assertEquals(expectedCount, records.size(), "应该生成N条变更记录");
    
    // 5. 执行策略
    List<ChangeRecord> executionResults = strategyService.executeStrategy("strategy-id", filePaths, config);
    
    // 6. 断言执行结果
    assertEquals(expectedCount, executionResults.size(), "应该执行N条变更记录");
    for (ChangeRecord record : executionResults) {
        assertChangeRecord(record, true, "SUCCESS");
    }
    
    // 7. 断言文件系统变化
    assertFileExists(testFile, false);
}
```

## 测试场景分类

### 1. 基础功能测试
- **策略注册测试**：验证策略是否正确注册
- **配置完整性测试**：验证所有配置字段是否定义
- **基本信息测试**：验证策略ID、名称、版本等基本信息

### 2. 核心功能测试
- **正常场景测试**：验证策略在正常情况下的行为
- **批量处理测试**：验证策略处理大量文件的能力
- **参数组合测试**：验证不同参数组合的效果

### 3. 边界条件测试
- **空列表测试**：验证空文件列表的处理
- **单个文件测试**：验证单个文件的处理
- **最大数量测试**：验证策略处理最大数量文件的能力

### 4. 异常处理测试
- **非存在文件测试**：验证非存在文件的处理
- **无效参数测试**：验证无效参数的处理
- **权限错误测试**：验证权限错误的处理

### 5. 过滤功能测试
- **关键词过滤测试**：验证包含/不包含关键词的过滤
- **类型过滤测试**：验证文件类型的过滤
- **大小过滤测试**：验证文件大小的过滤

## 文件收集策略测试用例示例

### 测试场景1：策略注册和基本信息验证
**目的**：确保file-collection策略在策略注册器中可用
**断言**：
- 策略不为null
- 策略ID正确
- 策略名称正确

### 测试场景2：配置字段完整性测试
**目的**：确保所有必要的配置字段都已定义
**断言**：
- 配置不为null
- 包含targetDirectory字段
- 包含targetType字段
- 包含similarityThreshold字段
- 包含collectionSuffix字段
- 包含mustContainKeywords字段
- 包含mustNotContainKeywords字段

### 测试场景3：相似文件归类测试
**目的**：验证相似文件能够被正确归类到合集文件夹
**测试数据**：
- 创建3个相似文件：周杰伦-青花瓷.mp3, 周杰伦-青花瓷.flac, 周杰伦-青花瓷.wav
- 相似度阈值：0.9
**断言**：
- 分析阶段生成3条变更记录
- 所有记录的changed状态为true
- 所有记录的状态为PENDING
- 执行后文件被移动到合集文件夹
- 源文件不存在

### 测试场景4：关键词过滤测试
**目的**：验证必须包含和必须不包含的关键词过滤功能
**测试数据**：
- 创建4个文件：
  - CD1-歌曲1.mp3（包含CD关键词）
  - CD2-歌曲2.mp3（包含CD关键词）
  - Album-歌曲3.mp3（包含Album关键词）
  - 普通歌曲.mp3（不包含任何关键词）
- 必须包含关键词：CD,系列,合集
- 必须不包含关键词：下载,Album,群星
**断言**：
- 只有CD1-歌曲1.mp3和CD2-歌曲2.mp3被归类
- Album-歌曲3.mp3被排除（包含必须不包含的关键词）
- 普通歌曲.mp3被排除（不包含必须包含的关键词）

### 测试场景5：非相似文件不归类测试
**目的**：验证不相似的文件不会被归类
**测试数据**：
- 创建3个不相似的文件：
  - 周杰伦-青花瓷.mp3
  - 林俊杰-江南.mp3
  - 蔡依林-倒带.mp3
- 相似度阈值：0.9
**断言**：
- 分析阶段生成3条变更记录
- 所有记录的changed状态为false
- 执行后文件保持原位置

### 测试场景6：多个文件批量归类测试
**目的**：验证批量处理多个文件的功能
**测试数据**：
- 创建10个相似文件
**断言**：
- 分析阶段生成10条变更记录
- 执行阶段成功处理所有文件
- 所有文件被移动到合集文件夹

### 测试场景7：空文件列表处理测试
**目的**：验证空文件列表的处理
**断言**：
- 分析阶段返回空列表
- 执行阶段返回空列表

### 测试场景8：非存在文件处理测试
**目的**：验证非存在文件的处理
**断言**：
- 分析阶段返回空列表
- 执行阶段返回空列表

## 测试用例执行计划

### 第一阶段：基础功能测试（优先级：高）
- 所有策略的注册测试
- 所有策略的配置完整性测试
- 所有策略的基本信息测试

### 第二阶段：核心功能测试（优先级：高）
- 每个策略的2-3个核心功能测试
- 覆盖主要功能分支

### 第三阶段：边界条件测试（优先级：中）
- 空列表测试
- 单个文件测试
- 最大数量测试

### 第四阶段：异常处理测试（优先级：中）
- 非存在文件测试
- 无效参数测试
- 权限错误测试

### 第五阶段：过滤功能测试（优先级：低）
- 关键词过滤测试
- 类型过滤测试
- 大小过滤测试

## 测试覆盖率目标

- **代码覆盖率**：≥80%
- **分支覆盖率**：≥75%
- **功能覆盖率**：100%（所有策略的所有功能）
- **场景覆盖率**：≥90%（正常、边界、异常场景）

## 测试用例维护

### 添加新策略时
1. 创建策略测试类，继承StrategyTestBase
2. 添加策略注册测试
3. 添加配置完整性测试
4. 添加核心功能测试（至少3个）
5. 添加边界条件测试（至少2个）
6. 添加异常处理测试（至少2个）

### 修改策略功能时
1. 识别受影响的功能
2. 更新相关测试用例
3. 添加新的测试用例覆盖新功能
4. 运行所有测试用例确保回归

### 修复Bug时
1. 添加失败的测试用例复现Bug
2. 修复Bug
3. 验证测试用例通过
4. 运行所有测试用例确保回归

## 测试用例命名规范

- **测试类命名**：{StrategyName}StrategyTest
- **测试方法命名**：test{ScenarioName}
- **辅助方法命名**：{action}{Target}（如：createTestFile、assertChangeRecord）

## 测试数据管理

- **临时目录**：使用Files.createTempDirectory创建
- **测试文件**：使用createTestFile辅助方法创建
- **清理机制**：在@AfterEach中自动清理临时文件
- **独立性**：每个测试方法使用独立的临时目录

## 断言消息规范

- **中文断言消息**：使用清晰的中文描述
- **上下文信息**：包含足够的上下文信息
- **期望vs实际**：明确说明期望值和实际值
- **可读性**：消息简洁明了，易于理解

## 测试执行和报告

### 本地测试
```bash
# 运行所有测试
mvn test

# 运行特定策略测试
mvn test -Dtest=FileCollectionStrategyTest

# 运行特定测试方法
mvn test -Dtest=FileCollectionStrategyTest#testSimilarFilesCollection
```
